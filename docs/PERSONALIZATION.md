## 2. Bigram Language Model (`BigramModel`)

### 2.1 Design & Memory Footprint
- **Structure**: Two-level hash table (`std::unordered_map<std::string, std::vector<BigramEntry>>`).
- **Hard Size Cap**: Bounded by default to 50,000 bigram pairs (`config.max_bigrams`).
- **Pruning Strategy**: When total pairs exceed capacity, the model automatically prunes single-occurrence pairs (frequency $\le 1$) and trims to 90% capacity, guaranteeing that memory usage remains strictly under **5 MB**.
- **Latency**: Next-word prediction lookup runs in $\mathcal{O}(1)$ hash time plus a small sort on at most 5–15 candidates ($< 15\,\mu\text{s}$ per keystroke).

### 2.2 Prediction & Candidate Scoring
When a preceding word $w_1$ is committed:
1. **Pre-Typing Suggestions**: If the user has not typed any Latin keys yet (`raw_input == ""`), the suggestion panel can display top bigram predictions for $w_1$ (e.g., after committing `আমার`, suggestions show `নাম`, `সোনার`, `দেশ`, `বন্ধু`).
2. **Context-Aware Ranking**: When typing the next word $w_2$, each candidate word $c$ generated by phonetic transliteration receives a log-linear context boost:
   $$\text{score}(c) = \text{base\_score}(c) + \lambda_{\text{bi}} \log_{10}(P(c \mid w_1) \times 1000 + 1)$$
   This ensures that contextually appropriate words (e.g. `খবর` following `কি`) appear at Rank 1 over less likely homophones.

### 2.3 Optional Trigram Support
Trigram prediction $P(w_3 \mid w_1, w_2)$ is implemented behind the `config.enable_trigram` configuration flag. If enabled, the model evaluates trigram counts for the pair $w_1, w_2$, falling back to bigram $P(w_3 \mid w_2)$ when trigram context is sparse.

## 3. Personal Dictionary & Shortcut Expansion (`PersonalDictionary`)

### 3.1 Shortcut & Snippet Expansion
Users can register custom text shortcuts that immediately expand into phrases, email addresses, or common greetings:
- E.g., `amr` $\rightarrow$ `আমার`
- E.g., `thx` $\rightarrow$ `অনেক ধন্যবাদ`
- E.g., `addr` $\rightarrow$ `ঢাকা, বাংলাদেশ`

When the input matches an active shortcut, the engine injects the expansion at **Rank 1** with `CandidateType::SHORTCUT_EXPANSION` and an elevated score of `15000.0`.

### 3.2 Atomic File Persistence
To prevent file corruption during sudden application crashes, battery death, or power loss:
1. New data is serialized to a temporary file: `${filepath}.tmp`.
2. The file stream is flushed to disk.
3. The temporary file replaces the target file via atomic filesystem rename (`std::rename` / POSIX `rename`).

### 3.3 Corruption Recovery
If the personal dictionary file is corrupted (e.g. invalid bytes, truncated lines from external edits):
1. `PersonalDictionary::load_from_file` parses all valid lines using a fault-tolerant reader.
2. If invalid lines are detected, a full backup of the original file is preserved at `${filepath}.bak`.
3. The recovered, clean records are immediately written back atomically.
4. The engine logs the recovery event and continues operating without throwing exceptions or crashing.

## 4. Proper-Noun Handling & Dynamic Learning

1. **Phonetic Generalization for Unseen Names**:
   Names not in the foundation dictionary (e.g., `Rahim`, `Karim`, `Sumon`, `Mehedi`, `Tanvir`, `Sakib`, `Chowdhury`) are accurately transcribed via beam-search lattice transliteration.
2. **Automatic Word Learning**:
   When the user commits or selects a name, the engine automatically records it in dynamic memory and the personal dictionary (`learn_word(name, 200)`).
3. **Subsequent Elevation**:
   On future keystrokes, the newly learned name is recognized as a familiar user word (`personal_dictionary.contains_word(name)`), receiving a $+800.0$ personal familiarity score boost that ranks it at the top.

## 5. Privacy, Security & Reset Capabilities

- **Zero Telemetry / Local Only**: All learning, bigrams, and shortcuts remain strictly local on the user's device. No network calls are made.
- **Secure Field Auto-Bypass**: In password or PIN fields (`secure_mode == true`), all dynamic learning, bigram updates, and undo recordings are strictly disabled. Nothing typed in secure fields is ever written to disk or learned.
- **Full Reset Command**:
  Calling `engine.clear_personal_data()` wipes:
  - All learned words in memory.
  - All bigram transitions.
  - All shortcuts and snippets.
  - Deletes all local persistent storage files (`.tsv`, `.bak`, `.tmp`).
- **Export / Import**:
  Users can cleanly export (`export_personal_data`) or import (`import_personal_data`) their personal dictionary in standard human-readable TSV format.
